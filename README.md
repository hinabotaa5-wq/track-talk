# TrackTalk

陸上競技のファン・選手・指導者が、大会・記録・レースについて匿名で語り合い、クラブチームの仲間や練習相手を見つけられるコミュニティです。都道府県陸協と国際大会の日程は自動で取り込み、月ごとの大会一覧として表示します。

## 使い方

スマホ前提の画面で、下部のタブ（ホーム／大会／コーチ／ケガ／マイページ）から移動します。PC では同じタブがヘッダーに並びます。自己紹介の欄はありません。ニックネーム（10文字まで）は任意で、マイページで公開をオンにした人だけ投稿の詳細に表示されます（既定は非公開、コメントには出ません）。いいねがついた投稿が30件以上ある公開中の人には「投稿マスター」のバッジが出ます（本人は隠せます）。

### 登録・ログイン

- メールアドレスとパスワード（8文字以上）、または Google アカウントで登録・ログインします（Supabase Auth）。メール登録では確認メールが届きます。パスワード再設定もできます。
- 登録には利用規約とプライバシーポリシーへの同意チェックが必要です。
- ログインしなくても、ホームの投稿一覧・詳細・コメント、大会タブ・県ページ（`/prefectures/{code}`）、ケガタブ、メモタブは見られます（メモタブは空の画面を見せ、書こうとしたりボタンを押したりするとログイン画面へ案内します）。大会一覧と県ページはサーバーで描いて sitemap に載せています。投稿・マイページ・いいね・保存・コメント・通報にはログインが必要です。

### ホーム（`/`）

- 投稿をカードで並べます（スマホ2列、PC 3〜4列、20件ずつ）。
- 並び替え: **人気**（直近14日の投稿をいいね数順）／**新しい順**／**募集**／**レビュー**（シューズ・スパイク一覧）／**保存**
- キーワード検索: タイトル・本文・募集の各項目を部分一致で探します。都道府県名で活動場所の募集も見つかります。
- 「今日開催中」: 主要大会の開催日に実況スレッドへの入口を出します（スレッドは1日1つ、投稿者は「TrackTalk」）。タイムテーブル登録済みの大会では「いま実施中」の種目も出ます。
- 左下の「＋」ボタンで投稿（`/upload`）を開きます。

### コーチ（`/coaching`、準備中）

オンラインコーチングは準備中で、このタブでは説明と「コーチを募集しています」の告知だけを出します（ログイン不要）。料金まわりは `STRIPE_SECRET_KEY` があるときだけ動き、ない間は支払いなしのデモ版（招待コード制）です。

- 「応募する」で応募画面（`/coach/apply`、ログインが必要）を開きます。入れるのは枠（コーチ／社会人・大学生）・担当種目（21種目から複数）・記録・成績・競技年数・顔写真（必須）だけです。運営が承認か見送りにし、承認後は変えられません。
- コーチ一覧（`/coaches`、ログイン不要）には承認済みコーチの写真・記録・★の平均と件数が並びます。承認済みコーチは「受付中」と1日の上限（1〜20本、初期値5本）を切り替えます。
- フォーム添削: 管理者が作る招待コード（8文字、1人1回）で `/coaching/new` から依頼します。種目（最初は100m）・見てほしい点（選択式）・動画（30秒まで、非公開）を選び、目安は翌日の12時です。依頼は受付中のコーチに順番に回り（1人が同時に持てるのは2本まで、★5件以上で平均★3未満は除外）、30分で引き受けなければ次へ回ります。返答は良い点1つ・直す点1〜2つ・おすすめドリル1つ（各300文字まで）と任意の見本動画で、連絡先らしき文字は送れません。★評価と「ここがわからなかった」（1回、コーチは補足を1回）があります。期限切れの片付けは `coaching-tick`（1分ごと）が行います。
- パーソナル指導: 承認済みコーチが誓約してから作るプラン（期間2週間・1か月か単発7日以内、2,000円から、上限なし、定員1〜50人、1人10個まで）に申し込みます。連絡先らしい文字は書けず、コーチは48時間以内に引き受けるか断ります。18歳未満はコーチが引き受けたあと保護者が72時間以内に同意ページから同意すると始まります。期間中のやりとり（文字2000字まで・非公開動画30秒まで）は1年読めて、その後 tick が消します。支払い中は `/coaching/personal/{id}` から Stripe Checkout で払います（コーチ引き受け後72時間以内）。取り分は添削70％・パーソナルは手数料20％引き（「初年10％」付きは10％引き）で、月に1回まとめて送金します。
- 保護者の同意メール: 本人が入れたアドレス宛に Resend でリンクを送ります（トークンは本人に返さない、1日5回まで）。手元では `MAIL_DEV_LOG=1` で本文をログに出せます。

### レビュー（`/?sort=review`、`/reviews/[id]`）

- シューズ／スパイクの商品カードをレビュー数・平均★順に並べます。見るだけならログイン不要です。
- 投稿はログインが必要で、1商品につき1人1件（削除して書き直す）。商品は管理者が登録します。
- 種目で絞ると、その種目の人のレビューだけでの平均★ランキング（3件以上の上位5つ）が出ます。

### 投稿（`/upload`）

投稿の種類は5つです（ケガの投稿は「ケガ」タブから行います）。

| 種類 | 内容 | 主なルール |
| --- | --- | --- |
| 文章 | 詳細・写真のいずれかでスレッドを立てる | 詳細10000字まで。詳細はフィードのカードにも表示。写真は1枚（10MB まで、送る前に長辺2048pxに縮める） |
| YouTube の URL | 動画を引用してスレッドを作る | サムネイルは YouTube から取得。詳細はフィードのカード見出しに表示。1動画1スレッドで、既にあればそのスレッドの詳細を開く。Instagram の URL も同じ。Instagram は表紙の画像を任意で付けられ、付けるとフィードのカードに出る |
| 自分の動画 | 撮った動画をアップロード | タイトル入力なしで投稿でき、詳細はフィードのカード見出しに表示。動画は100MB まで。ブラウザから直接アップロードし、長辺1280px相当に縮める |
| クラブチームの募集 | チームのメンバーを募る | 活動場所（都道府県＋詳細）・時間・男女比・年齢・SNS の URL（4件まで）・写真1枚まで |
| 練習相手募集 | 一緒に練習する相手を募る | 場所・日時（未来のみ）・種目・人数（1〜99人）・詳細（2000字まで） |

自分の投稿は編集・削除できます。他の人の投稿には、いいね・保存・コメント（2000字まで）・通報ができます。

### 練習相手募集の流れ

1. 募集者が日時・場所・種目・人数を投稿する
2. 参加したい人が「参加したい」で申請する → 募集者に通知
3. 募集者が **承認** か **見送り** にする → 承認数が定員で「満員」
4. 終わったら募集者が **解散** する → 全員に評価のお願いを通知
5. お互いを **良い／普通／悪い** と、ひとこと（200字まで、1回だけ）で評価する。評価は練習の投稿に表示される

満員か解散の後は、募集者と承認された参加者だけがコメントできます。

### ケガ（`/injury`）

怪我で走れない人が、同じケガのグループに集まって気持ちや経過を分け合うタブです。タブ自体はログインなしで開けますが、グループの中の閲覧・投稿は参加者だけで、ホームのフィードには出ません。

- グループはハムストリングの肉離れ・太もも前の肉離れ・捻挫・アキレス腱炎・ジャンパー膝・シンスプリント・肩の痛み・肘の痛みの8つと「その他」です。未参加のグループをタップすると質問に1問ずつ答えて入れます（「その他」ではケガの名前も書く）。
- グループの中は、怪我直後から大会復帰までの5段階（安静中／リハビリ中／ジョグ再開／練習に復帰／大会に復帰）のロードマップです。投稿できるのは自分のいまの段階だけで、段階は前後・飛ばして変えられます。
- その後の経過を時系列で追加できます（1投稿50件、1件2000字まで）。いいねは「わかる」と表示されます。
- **みんなの復帰データ**（`/injury/stats`、ログイン不要）で、段階ごとの人数と投稿から最初の報告までの日数の中央値を見られます（5人そろった段階だけ）。
- **データ**タブ（`/injury/data`、ログイン不要）は閲覧だけで、入るときの回答と「復帰までにやったこと」の集計（5人そろった項目だけ）を予防に役立てます。

### エグ練大会（`/menu-contest`）

- 冬（11月〜3月）は2週間ごとに「一番エグかった練習」を集めて1位を決めます。シーズンは11月の最初の月曜に始まります。
- 1週目月曜〜2週目水曜が応募（1人1件、100文字まで、締め切りまで書き直し・取り消し可）、木曜に運営がトップ3を選び、金〜日が投票（1人1票、入れ直し可、自分の応募には入れられない）、翌週月曜に結果を出します。同票なら全員1位です。
- 開催中はホームのヘッダー下に段階と締め切りまでの残り時間を出します（残り24時間で赤表示）。

### 大会（`/competitions`）

- 月と地域（47都道府県または「国際」）を選んで、その月の大会を一覧にします（初期表示は今月）。最後に選んだ地域はブラウザに保存します。
- 各大会には日程・会場と主催者のページへのリンクがあります。
- **国内主要大会**（`/competitions/major-domestic`）と**今後の世界陸上・オリンピック**（`/competitions/major-hosts`）の専用ページもあります。
- データは自動で取り込んでいます（下の「大会データの取り込み」）。

### 通知

ヘッダーのベルに未読数が出ます。開くと既読になり、「すべて既読」もできます。種類は、自分の投稿へのコメント／参加申請／参加の承認／解散と評価のお願い／ケガの投稿の経過報告（「わかる」か保存をした人へ）の5つです。

### マイページ（`/me`）

メニューは、自分の投稿・保存した投稿・自分のケガ履歴・ニックネームの変更・メールアドレスとパスワードの変更・バッジ・通知・お問い合わせ・ガイドライン・利用規約・プライバシーポリシー・ログアウト・退会の順です。

- 感覚メモ: 練習で感じた感覚を300字までのひとことで書き溜めます（1日に1つ、書けるのはその日＝日本時間の今日の分だけ、自分にしか見えない）。書くとビンに粒が1つ落ち、6粒で満杯になって次のビンへ。連続日数とこれまでの数を表示します。書いたあとは直せません（削除はできます）。前のまとめ以降に6個たまるたびに AI のふりかえりまとめを作れます（時間の制限なし、提供中のみ）。
- 記録のタブ（`/memo?tab=records`）の上に、この30日で自己ベストを更新した人の数を種目ごとに出します（5人に満たない種目は出さない）。
- 通知（`/me/push`）: この端末でプッシュ通知をオン・オフし、テスト通知を送れます。毎月1日19時に「大会の記録、残せていますか？」が届きます。
- 退会: 「退会する」と入力すると投稿・コメント・いいね・保存・通知・感覚メモなどのデータとログイン用アカウントが削除されます。パーソナル指導の進行中や、通報の対応中は退会できません。

### 安全のための仕組み

- コミュニティガイドライン（`/guidelines`）で誹謗中傷・権利侵害・個人特定情報・練習会の悪用などを禁止しています。
- 投稿・コメント・練習の評価のひとことは理由を選んで通報できます。
- 管理者（`profiles.is_admin = true`）は管理者画面（`/admin`）で通報・問い合わせを見て、投稿やコメントを非表示にできます。「数字」タブでは週ごとの利用状況を件数と人数だけで見られます。
- API は接続元ごとに回数を制限しています（書き込みは1分に30回、通報とお問い合わせは1時間に10回まで）。アクセス数は Umami で計測しています。

## 構成

| 場所 | 役割 | 技術 |
| --- | --- | --- |
| `apps/web` | 画面・ルーティング | Next.js 16 / React 19 / TypeScript / Tailwind CSS 4 / Zod |
| `apps/api` | 業務ロジック・認可（`/v1`） | Go 1.25 / chi / pgx / sqlc / golang-migrate |
| PostgreSQL + Supabase Auth | DB・認証 | マイグレーションは `apps/api/migrations` |
| Cloudinary | 画像・動画の保存 | API が署名を発行し、ブラウザから直接アップロード |
| Gemini API | 都道府県の大会日程ページから大会を抽出 | `apps/api/internal/competitions` |

業務ロジックは Go API に集約しています。Next.js から PostgREST でテーブルを直接操作しません（全テーブルで RLS 有効）。

```
apps/
  api/
    cmd/api/                 API サーバー
    cmd/migrate/             マイグレーション
    cmd/importcompetitions/  大会日程の取り込み
    cmd/importmajors/        五輪・世界陸上の開催地の取り込み
    cmd/importdomestic/      国内主要大会の取り込み
    internal/                auth, cloudinary, competitions, config, db, httpx, migrate
    migrations/  queries/    SQL（queries は sqlc 用）
  web/
    app/  components/  lib/  e2e/  emails/
docs/launch.md               公開チェックリスト
```

## ローカル起動

必要なもの: Go 1.25、Node.js 22、Docker（PostgreSQL 用）

```bash
cp .env.example .env
# .env に Supabase の URL / anon key / JWT secret（必要なら Cloudinary）を入れる
make db            # docker の PostgreSQL を 127.0.0.1:55432 で起動(開発用。本番の Supabase には接続しない)
make migrate
make api        # http://localhost:8080/health
# 別ターミナル
cd apps/web && npm install && cd ../..
make web        # http://localhost:3000
```

SQL を変更したら `make sqlc` でコードを再生成します（sqlc が必要）。

## 環境変数

`.env.example` が雛形です（全項目）。API はリポジトリ直下の `.env` も読み込みます。本番の API は `deploy/cloud-run/env.example.yaml` をコピーした `env.yaml`（Git 管理外）から入れます。

| 変数 | 説明 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL の接続文字列（必須） |
| `SUPABASE_URL` / `SUPABASE_JWT_SECRET` / `SUPABASE_JWT_AUD` | JWT の検証（URL か secret のどちらかが必須） |
| `SUPABASE_SERVICE_ROLE_KEY` | 退会時に Auth ユーザーを削除する |
| `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` | アップロード署名 |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | Web Push 通知。空なら通知は送らない |
| `COACHING_ENABLED` / `NEXT_PUBLIC_COACHING_ENABLED` | オンラインコーチングを使えるようにする。本番では空のまま（空なら API は 404、画面は Not Found） |
| `COACHING_TICK_SECRET` / `REMINDER_SECRET` | tick・月1回のお知らせを呼ぶ秘密の値。`deploy/cloud-run/` のスクリプトが作って入れる |
| `SENSE_SUMMARY_ENABLED` / `NEXT_PUBLIC_SENSE_SUMMARY_ENABLED` | 感覚メモの AI まとめの開閉（両方揃える） |
| `SMTP_*` / `RESEND_API_KEY` / `MAIL_FROM` | 保護者の同意リンク送付。SMTP があれば優先。`MAIL_DEV_LOG=1` で手元確認 |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` / `STRIPE_CONNECT_WEBHOOK_SECRET` | 支払いと送金（空なら支払いなしのデモ版） |
| `GEMINI_API_KEY` | 都道府県の取り込みと感覚メモのまとめ |
| `GEMINI_SUMMARY_MODEL` / `SENSE_SUMMARY_DAILY_LIMIT` | 感覚メモのまとめのモデル（空なら `gemini-3.5-flash-lite`）と、全員の1日の上限（空か 0 なら無し） |
| `NEXT_PUBLIC_API_BASE_URL` / `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `NEXT_PUBLIC_SITE_URL` | ブラウザに公開される値 |

フロントに置くのは `NEXT_PUBLIC_*` と **anon key のみ**です。`service_role`・`DATABASE_URL`・Cloudinary の secret・Gemini のキーは API／ホスティング／GitHub Secrets の秘密領域だけに置いてください。

## 大会データの取り込み

`apps/api` で実行します。

```bash
go run ./cmd/importcompetitions                           # 期限切れの国際大会と都道府県を取り込む
go run ./cmd/importcompetitions -prefecture 13            # 指定した県だけ（00 は国際大会）
go run ./cmd/importcompetitions -prefecture 46 -dry-run   # DB に書かずに結果を表示
go run ./cmd/importmajors                                 # 五輪・世界陸上の開催地
go run ./cmd/importdomestic                               # 国内主要大会（-dry-run で DB に書かず表示）
```

- **都道府県**: 各陸協の日程ページから Gemini で大会情報に変換します。前回から 10 日経った県が対象で、上限（`GEMINI_DAILY_REQUESTS`、既定 15）に収まるところまで処理します。
- **国際大会**: World Athletics と Diamond League のカレンダーから取り込みます（Gemini なし、7 日ごと）。
- **五輪・世界陸上の開催地**: Wikipedia から取り込みます。
- **国内主要大会**: 日本陸連と日本学生陸上競技連合のページから取り込みます（Gemini なし）。

定期実行は `.github/workflows/imports.yml` です（毎日 06:00 JST が大会取り込み、4月・10月の1日が開催地と国内主要大会）。手動実行は Actions の「Imports」から行えます。

## テスト・Lint

```bash
make test-api                                  # Go（統合テストは DATABASE_URL の PostgreSQL が必要）
# make は常にローカル DB(55432)に接続する。.env の DATABASE_URL は make 経由では使われない
make test-web                                  # Vitest
cd apps/web && npm run lint && npx tsc --noEmit
cd apps/web && npm run test:e2e                # Playwright
```

CI（`.github/workflows/ci.yml`）は push／PR ごとに API テスト（PostgreSQL サービスコンテナ付き）、Web の Lint・単体テスト・型チェック、ログインから文章投稿までの E2E を実行します。その E2E が落ちると CI が失敗します。

## デプロイ

- **API**: Cloud Run（東京）。マージしても自動ではデプロイしない。GitHub の Actions →「Deploy API」→ Run workflow で `main` をデプロイする（`.github/workflows/deploy-api.yml`）。予算を超えると自動で API を止める。初回の作り方は [docs/cloud-run-deploy.md](docs/cloud-run-deploy.md)。
- **Web**: Netlify（`apps/web`）。マージしても自動ではデプロイしない（`netlify.toml` の `ignore`）。Actions →「Deploy Web」→ Run workflow でフックを呼んで本番に出す。
- **DB / Auth**: Supabase

公開前の確認事項は [docs/launch.md](docs/launch.md) を参照してください。料金・無料枠・商用条件は変わるため、公開直前に各公式ドキュメントで確認してください。

## 管理者

`profiles.is_admin = true` を SQL で自分のユーザーに設定すると、管理者画面（`/admin`）と管理用 API を使えます。マイページにはリンクを出さないので、URL を直接開きます。画面は一覧の閲覧用で、非表示の操作は API（`/v1/admin/...`、通報・問い合わせ・投稿／コメントの非表示など）で行います。


### Docker で現在のコードをプレビュー

このフォルダで `make local` を実行し、http://localhost:3000 を開きます。
未保存変更もビルドに含まれます。既存の開発用DBとは別のプレビュー専用DBと認証を使い、外部の本番サービスには接続しません。
コーチング機能もローカルで有効です。デモユーザーは `demo@tracktalk.local` / `demo-password` です。
縦・横動画のサンプルを2件投入します。Googleログインと外部サービスへのアップロード・決済はプレビューの対象外です。
停止は `make local-down`（プレビュー用DBのデータは保持）です。
