# 感覚メモのAIまとめの回数制限

## Tier 0を前提にした初期設定

2026年10月27日にAI Studioの「track talk」プロジェクトを、ユーザーの承認でTier 0（無料枠）へ戻した後に確認した。`gemini-3.5-flash-lite` は500回/日、15回/分、入力25万トークン/分。切り替え前の比較表示は差分が丸められていたため、切り替え後の実際の表示を根拠とする。

- 全員合計で直近24時間400回（`SENSE_SUMMARY_DAILY_LIMIT=400`）。
- 全員合計で直近1分10回（`SENSE_SUMMARY_MINUTE_LIMIT=10`）。
- 本人のまとめ保存は日本時間の1日3回まで（従来どおり）。
- 1回に送るのは300文字以下のメモ6個。要約の生成は出力2,048トークンまで。大会の抽出にはこの出力制限を適用しない。

400回は確認した無料の日次枠の80%、10回は分単位枠の約67%。他の処理・運営での試験にも余裕を残すための初期値であり、Googleの無料枠そのものではない。実際の上限はモデル・プロジェクト・利用階層で変わるため、変更時にはAI Studioを再確認する。

[Googleの制限説明](https://ai.google.dev/gemini-api/docs/rate-limits)では、日次枠は太平洋時間の深夜にリセットされる。アプリ全体は日付でリセットせず直近24時間を数えるため、日本時間や夏時間の境界で二重に使える枠は発生しない。個人の1日3回は日本時間のまま。

## 安全の仕組み

APIを呼ぶ直前にDBで試行枠を予約する。成功分だけでなく、通信失敗・Googleのエラー・不正な応答・保存失敗でも回数を返さない。同時に複数の利用者・APIインスタンスが頼んでも、DBのトランザクションロックで数の確認と予約を直列化する。外部APIの応答待ちのあいだはDBロックを持たない。本文・利用者ID・応答は回数管理表に保存しない。

感覚メモ不足など、APIを呼ばないリクエストは試行枠を使わない。期限切れの試行記録は次の予約時に消す。マイグレーション113で導入前25時間の成功分も初期登録する。導入前の失敗回数は過去に記録していないため復元できない。

空・未設定なら400回/24時間、10回/分を使う。`0`を明示するとその上限を無効にするため、本番の無料運用では指定しない。上限に達したときはGeminiを呼ばず、既存の「いまはまとめを作れません」の応答を返す。自動再試行はしない。

## 本番反映

先にAPIを更新してマイグレーション113を適用する。その後、古い環境変数`SENSE_SUMMARY_DAILY_LIMIT=20`を差分更新する。

```sh
gcloud run services update track-talk-api \
  --project refined-bolt-493709-a8 --region asia-northeast1 \
  --update-env-vars SENSE_SUMMARY_DAILY_LIMIT=400,SENSE_SUMMARY_MINUTE_LIMIT=10
```

Webの更新やNetlifyの配備は不要。

回数制限自体は課金プランの変更や金額上限ではない。今回、別の運用操作としてAPI用プロジェクト `gen-lang-client-0591124513` の請求先との接続を外し、AI Studioで無料枠と表示されることを確認した。Cloud Run本番プロジェクト `refined-bolt-493709-a8` の課金は変更していない。将来有料枠に戻す場合は回数上限だけで費用ゼロを保証できないため、課金設定を別途確認する。

Google側の1日（America/Los_Angeles）にも400回の上限を適用する。夏時間の終了で1日が25時間になる日も、直近24時間の上限だけで枠を使い切るのを防ぐ。

大会の県別自動取り込みは別モデル `gemini-3.8-flash` を使用し、1回の定期実行は既存の15リクエストまで。無料枠の20回/日・5回/分に余裕を残す。県内の複数ページ間も15秒あける。手動実行を重ねるとこの20回の枠を共有するので注意する。要約用Flash-Liteの400回から県別取り込みの15回を差し引く必要はない。
