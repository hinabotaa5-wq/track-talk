# 感覚メモのAIまとめの回数制限

## Tier 0を前提にした初期設定

2026年10月27日にAI Studioの「track talk」プロジェクトで無料枠との比較を確認した。`gemini-3.5-flash-lite` は無料枠との比較差分から500回/日、10回/分、入力25万トークン/分。現在のプロジェクト自体はTier 1で、前払いクレジット不足が表示されている。比較表示は課金プランの変更ではない。

- 全員合計で直近24時間200回（`SENSE_SUMMARY_DAILY_LIMIT=200`）。
- 全員合計で直近1分5回（`SENSE_SUMMARY_MINUTE_LIMIT=5`）。
- 本人のまとめ保存は日本時間の1日3回まで（従来どおり）。
- 1回に送るのは300文字以下のメモ6個。要約の生成は出力2,048トークンまで。大会の抽出にはこの出力制限を適用しない。

200回は確認した無料の日次枠の40%、5回は分単位枠の50%。他の処理・運営での試験にも余裕を残すための初期値であり、Googleの無料枠そのものではない。実際の上限はモデル・プロジェクト・利用階層で変わるため、変更時にはAI Studioを再確認する。

[Googleの制限説明](https://ai.google.dev/gemini-api/docs/rate-limits)では、日次枠は太平洋時間の深夜にリセットされる。アプリ全体は日付でリセットせず直近24時間を数えるため、日本時間や夏時間の境界で二重に使える枠は発生しない。個人の1日3回は日本時間のまま。

## 安全の仕組み

APIを呼ぶ直前にDBで試行枠を予約する。成功分だけでなく、通信失敗・Googleのエラー・不正な応答・保存失敗でも回数を返さない。同時に複数の利用者・APIインスタンスが頼んでも、DBのトランザクションロックで数の確認と予約を直列化する。外部APIの応答待ちのあいだはDBロックを持たない。本文・利用者ID・応答は回数管理表に保存しない。

感覚メモ不足など、APIを呼ばないリクエストは試行枠を使わない。期限切れの試行記録は次の予約時に消す。マイグレーション113で導入前24時間の成功分も初期登録する。導入前の失敗回数は過去に記録していないため復元できない。

空・未設定なら200回/24時間、5回/分を使う。`0`を明示するとその上限を無効にするため、本番の無料運用では指定しない。上限に達したときはGeminiを呼ばず、既存の「いまはまとめを作れません」の応答を返す。自動再試行はしない。

## 本番反映

先にAPIを更新してマイグレーション113を適用する。その後、古い環境変数`SENSE_SUMMARY_DAILY_LIMIT=20`を差分更新する。

```sh
gcloud run services update track-talk-api \
  --project refined-bolt-493709-a8 --region asia-northeast1 \
  --update-env-vars SENSE_SUMMARY_DAILY_LIMIT=200,SENSE_SUMMARY_MINUTE_LIMIT=5
```

Webの更新やNetlifyの配備は不要。

回数制限は無料課金への切り替えや金額上限ではない。現在のTier 1の鍵を使う限り、課金条件はTier 1のまま。クレジット不足（402）はこの変更で解消しない。無料で提供するときは無料枠で使えるプロジェクト・モデルであることを別途確認する。支払い・自動入金・課金プランはこの変更では操作しない。
