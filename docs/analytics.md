# 利用状況の計測

## 現在の実装

Umamiの既存のページ閲覧計測に、次の操作名を追加しています。APIが成功したときだけ数えます。検索は、空でない検索語でフォームを送信したときに数えます。

| イベント | 意味 |
| --- | --- |
| `onboarding_completed` | 未完成だったプロフィールのニックネーム・種目の保存成功。メール登録の送信やメール認証完了とは別 |
| `post_created` | 投稿の新規作成成功。編集は含まない |
| `post_liked` | 投稿へのいいねの成功。取り消しは含まない |
| `search_submitted` | 投稿一覧で検索を実行。検索解除は含まない |
| `race_record_created` | 競技会の記録の新規保存成功 |
| `race_record_updated` | 競技会の記録の編集成功 |

本文、検索語、トークン、アカウントIDをイベントのプロパティとして渡しません。Umamiに送るURL・参照元からクエリ・フラグメントを除去し、保護者のトークンを伏せます。ページ閲覧と追加の操作計測は本番の `track-talk.netlify.app` に限定します。遮断・通信失敗・Umami読み込み前の操作は欠測する場合があります。DBの確定件数とは一致を保証しません。

## PostHogの接続

接続先が未設定の間は、PostHogの読み込み・送信・ブラウザへの保存をしません。

1. [PostHog](https://app.posthog.com/signup)で無料アカウントとプロジェクトを作成します。無料枠に限定するため、支払いカードを登録しません。既存の支払い設定がある場合は、利用上限を管理画面で確認してください。
2. プロジェクトの設定で **Discard client IP data** を有効にします。コードでも `$ip` をダミー値にし、GeoIPを無効にしています。録画・自動収集・機能フラグ・アンケートなどはコードで無効です。
3. プロジェクトの公開キー（`phc_...`）と取り込み先を確認します。個人APIキーや管理用の秘密鍵は使いません。
4. `netlify.toml` の `[context.production.environment]` に `NEXT_PUBLIC_POSTHOG_KEY` と `NEXT_PUBLIC_POSTHOG_HOST` を設定します。取り込み先は `https://us.i.posthog.com` または `https://eu.i.posthog.com` を指定します。それ以外のホストはコードで読み込みを止めます。プロジェクト変更時はここを更新してください。管理用の秘密鍵は書きません。Netlify管理画面の設定を使うこともできますが、同じ変数については設定ファイルが優先されます。
5. Webを再ビルド・公開します。プライバシーポリシーの更新を含めて公開します。
6. 本番サイトを開き、PostHogのライブイベントで `$pageview` と操作イベントを確認します。失敗した保存やいいねの取り消しが追加されないこと、URLやプロパティに検索語・認証の値・本文がないことを確認します。

PostHogは共通の操作イベントに加えて、許可した画面への移動を `$pageview` として記録します。投稿の画面は `/posts/:id` にまとめます。対象外の画面には画面閲覧も操作も送りません。画面タイトル・参照元・検索条件を送信直前に取り除きます。

localStorageの匿名IDで同じブラウザの再訪を分析できます。アカウントの識別や別端末の統合はしません。共有端末は同じ匿名IDになり、保存領域の削除・別ブラウザでは別IDになります。登録の流れは `/register` → `/me/profile` → `onboarding_completed` を使って分析できますが、メール認証で端末が変わる場合は追跡がつながりません。

Reactの再実行による同じパスの連続計測を防ぎ、クエリだけの変更を追加のページ閲覧として送りません。自動の全クリック収集や録画を追加しないので、不要なイベントの増加を抑えます。

## DBに残す日別集計

管理者画面のタブ名は「利用状況」です。画面には、Umamiに送っていない機能の利用件数・利用アカウント数、アカウント単位の週別利用人数・継続率、問い合わせ・通報・コーチングの運営状況を表示します。日別表はコメント・感覚メモ・レビュー・退会、週別表は書いた人数・感覚メモ・退会に絞ります。Umamiと重複する投稿・いいね・競技会の記録の操作件数と、登録単独の件数は画面に表示しません。継続率の母数として登録者数は表示します。DBの日別集計の保存対象とAPIの応答は維持します。

APIのマイグレーション108を適用した時点から、登録（プロフィール初回作成）、投稿、コメント、いいね、感覚メモ、競技会の記録、商品レビュー、退会を日別に数えます。大会スレッドの自動作成は投稿に含めません。

`daily_usage_counts` に保存するのは、日本時間の日付・操作名・件数だけです。本文、アカウントID、投稿ID、端末情報は保存しません。DBのINSERTが成功した分を同じトランザクションで加算するため、処理がロールバックされれば件数も巻き戻ります。編集・削除で件数を減らさず、退会後も集計を保持します。同じいいねの再送（既存行との衝突）は増やさず、取り消した後の押し直しは増やします。これは利用者数や現在の保存件数とは別の、作成操作の累計です。

管理者の「利用状況」タブの「日ごとに残す件数」に表示します。直近90日を表示し、導入前の日は0として表示しません。初日は開始時刻以降のみ、当日は途中までの数字です。過去のデータの埋め戻しはしません。表示期間より古い集計もDBには残ります。

保存は最大8行/日と開始時刻1行です。定期ジョブ・新しい有料サービスは不要ですが、既存DBの容量や処理量の上限内での運用が前提です。アクセス数やページ閲覧数はUmamiで確認します。

本番反映時は、先にAPIを更新してマイグレーション108を適用し、次にWebを更新します。新しいWebは旧APIの応答でも既存の統計を表示できます。管理者以外は集計APIを参照できず、集計テーブルにもRLSを有効にしています。マイグレーション108を戻すと保存済み集計も削除されるため、戻す前に必要な集計を退避してください。

## Clarity

Clarityは導入しません。TrackTalkは未成年も対象に含み、[Clarityの公式説明](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-api)は18歳未満を対象とするサイト・アプリでの利用を避けるよう案内しています。受領したタグは読み込まず、Clarityへの送信は行いません。

## 無料枠と公開時の確認

料金・無料枠・保存期間は外部サービスの契約で変わります。コードではプロジェクト全体の利用量を管理できないため、公開前と運用中に管理画面で契約・利用上限・IP保存設定を確認してください。

- [Umami料金](https://umami.is/pricing)
- [PostHog料金](https://posthog.com/pricing)
- [PostHogのNext.js導入](https://posthog.com/docs/libraries/next-js)
- [送信前のデータ除去](https://posthog.com/tutorials/web-redact-properties)

公開時は、日別集計のマイグレーション適用、Webのビルド設定、本番でのイベント受信とデータ除去を確認します。設定ファイルに公開キーがあることだけでは、受信や外部サービス側の設定が完了した証拠にはなりません。
