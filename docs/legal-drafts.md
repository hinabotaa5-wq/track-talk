# 法務まわりの下書き（たたき台）

弁護士の無料Q&A（ココナラ・弁護士ドットコム）と関東総合通信局の回答をもとにした初期方針の下書き。
**どれも確定した文面ではない。** 本番の `/terms` などには、弁護士の確認と、ひなたさんの判断を経てから入れる。
「要確認」と書いた欄は、資金決済法の回答（投稿3）で覆りうるので、本番の文面が決まるまで外さない。

## 1. 利用規約に足す「当事者の立場」（下書き）

根拠: ココナラ回答1（(1)動画添削は運営者が契約の相手方、(2)サポートプランはコーチが契約の相手方）。
弁護士ドットコム回答1は「仲介にするか、運営者が間に入るかは設計次第。立場をサイト上に明示すること」という一般論。

> **第○条（取引の相手方）**
> 1. フォーム添削とフォーム添削の追加相談（販売を終了したチケットを含む）は、運営者が利用者に販売します。運営者は、承認したコーチに添削の業務を委託します。
> 2. サポートプラン（動画添削・大会サポート・対面指導などを含むコーチのプラン）は、プランを出しているコーチが利用者に販売します。運営者は、申し込みの場を提供します。
> 3. 代金の受け取りと、コーチへの支払いの方法は、別に定めます。（要確認: 資金決済法の回答待ち。収納代行・Stripe Connect での直接の支払いのどちらで書くかが決まっていない）

画面では、購入の前に `SellerNote`（`apps/web/components/seller-note.tsx`）で販売者を1行で示す。

## 2. 特定商取引法に基づく表記

- 運営者の分（(1)用）: `apps/web/app/legal/commerce/page.tsx`。`NEXT_PUBLIC_COACHING_ENABLED` が空の間は 404。
  - 所在地・電話番号は「請求があれば遅滞なく開示します」で省略する（ココナラ回答1の省略方法①）。実際に速やかに開示できる体制が前提。
  - 開示請求は、お問い合わせの種類「特商法表記の開示請求」（`disclosure`）か、メールで受け付ける。
  - 支払方法は「クレジットカード（Apple Pay・Google Pay を含む）、PayPay」の都度払い。チケットの新規販売は終了し、購入済みチケットの扱いと支払方法・返金の条件は「要確認」。
- コーチの分（(2)用）: まだ無い。コーチごとの表記（原則フル表記、表記要否のフラグ）は別の PR で作る。

## 3. 有料の1対1のやりとり

根拠: 関東総合通信局の回答（有料の1対1メッセージは電気通信事業の届出の対象。始める前に届出が必要で、受理まで約2〜4週間）。
`COACHING_MESSAGING_ENABLED` / `NEXT_PUBLIC_COACHING_MESSAGING_ENABLED` を、届出が受理されるまで空にしておく。

## 4. 取引条件の通知（フリーランス保護法3条）

根拠: 弁護士ドットコム回答2（運営者→コーチは業務委託。無雇用の個人事業主は特定業務委託事業者にあたらないので
60日以内の支払義務は不適用、3条の明示だけ必要。利用規約への同意だけでは足りず、案件ごとの明示が要る）。

- 対象は、運営者が販売する **(1) フォーム添削と、その追加相談だけ**。打診の画面で引き受ける前に9項目を見せ、
  引き受けたら `coach_work_orders` に書き留める（後から書き換えない）。文面は `apps/api/internal/httpx/work_order.go`。
- **(2) サポートプランへの拡張は、弁護士の回答（Q9）の後に決める。** 回答2は「(1)と(2)で違うかは商流が分からず答えられない」で、
  (2)に通知が要らないとは言われていない。
- 未確定: 支払期日の書き方（3,000円未満の繰り越しがあると1つの日付に決まらないため、「翌月15日、繰り越したら翌々月15日」と
  両方を書いている。Q6）と、画面での表示と記録で「電磁的方法による明示」として足りるか（メールも送るべきか。Q7）。
- 検査の欄は「検査をしない（送信した時に受け取ったものとする）」と仮に書いている。運営者が非表示にする運用との関係は要確認。

## 5. コーチごとの特商法表記（(2)用）

根拠: ココナラ回答1（サポートプランはコーチが販売者で、表記もコーチ。継続的な事業でなければ対象外の可能性）と、
判断シートの Q3・Q4 の決定（2026-10-28）。

- 表記の要否はコーチの自己申告。既定は「表記要」。不要にするにはチェックリストの全項目に当てはまると申告し、
  申告した版と日時を記録する。チェックリストは `apps/api/internal/httpx/coach_commerce.go` の `commerceExemptChecklist`（仮。Q5系の回答後に差し替え）。
- 運営は事業の実態が見えたら表記要に戻せる（管理画面「コーチの特商法の登録情報」）。戻したら本人は申告し直せない。
  この権限を利用規約に書く（下の条文案）。
- 氏名・住所・電話番号は全コーチ必須で、プランの公開前に登録する。表記要ならプランのページにフル表記で出す（省略方式は使わない。Q5 回答待ち）。
- 保管: 表示用のデータと分けた `coach_legal_identities` に、AES-256-GCM で暗号化して入れる。鍵は `COACH_IDENTITY_KEY`（DB とは別に管理）。
  読み書きは `coach_commerce.go` だけで行い、公開の API は表記要のコーチの分だけを出す（表記不要のコーチの分が公開 API に出ないことをテストで確認）。
  運営が見るのは管理画面からだけで、見るたびに目的・管理者・日時を `coach_identity_access_logs` に残す。管理者は二段階認証が必要（`STAFF_MFA_REQUIRED`）。
- 金庫用の別DBへの分離は、有料化して Supabase を Pro に上げるときに行う（読み書きが1ファイルに集まっているので、暗号化したまま移せる）。
- 保持期間（決定 2026-10-28）: 5年。起算点は「最後の取引が終わった時」と「コーチをやめた時」の遅いほう。過ぎたら日次の処理
  （`/internal/storage/cleanup`）で登録情報（`coach_legal_identities` の行）を消す。
  - コーチをやめた時: 本人がコーチをやめた時・審査で却下された時・退会（アカウント削除）した時。もう一度応募したら取り消す。
  - 最後の取引: 報酬の記録・報酬の支払い・添削の返却・パーソナル指導の終了／返金・追加相談の回答／補足／終了のうち一番遅いもの。
    やめた後に返金や残りの報酬の支払いがあれば、その時から数える。
  - 退会しても、開示請求・紛争対応のために登録情報は残す（アカウントの他のデータは今までどおり消える）。
    退会で取引の記録から本人が外れるので、退会の時点の最後の取引の日時を書き留めておく。
  - 残る課題: DB のバックアップに残った分は、バックアップの保存期間がたつまで消えない（金庫の DB に移すときも同じ）。
    表記の要否の申告記録（`coach_commerce_settings`）と運営の閲覧記録は登録情報ではないので、この処理では消さない。

利用規約に足す条文案:

> **第○条（コーチの販売者表示）**
> 1. サポートプランを出すコーチは、特定商取引法に基づく表記のため、氏名・住所・電話番号を運営者に登録します。表記が必要な間、これらはプランのページに表示されます。
> 2. 事業として販売していないコーチは、運営者の定める項目に当てはまることを申告して、表記を不要にできます。この場合も登録した情報は、開示請求と紛争の対応のためだけに運営者が保管します。
> 4. 運営者は、登録された情報を、コーチとしての最後の取引が終わった時とコーチをやめた時（退会を含みます）の遅いほうから5年間保管し、その後に削除します。退会しても、この期間は削除しません。
> 3. 運営者は、申告と異なり事業としての実態があると判断したときは、表記を必要とする設定に戻すことができます。

プライバシーポリシーに足す文案:

> コーチが登録した氏名・住所・電話番号は、特定商取引法に基づく表記に使います。表記を不要と申告したコーチの情報は公開せず、購入者からの開示請求と、紛争の対応のためにだけ利用します。これらは暗号化して保管し、運営者が閲覧したときは記録を残します。コーチとしての最後の取引が終わった時とコーチをやめた時（退会を含みます）の遅いほうから5年間保管し、その後に削除します。
